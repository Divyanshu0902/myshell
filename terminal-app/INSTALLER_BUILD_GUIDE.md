# apnaShell Windows Installer Build Guide

This guide documents exactly how the Windows installer is built for this project, including dependencies, resources, steps, and practical cautions.

## What You Are Building

The installer output is an NSIS `.exe` generated by `electron-builder` from the `terminal-app` project.

Final installer output path:

- `terminal-app/release/apnaShell Setup <version>.exe`

The installer packages:

- Electron app runtime
- renderer build (`dist/`)
- Electron main/preload files (`electron/`)
- bundled shell executable (`shell-core/myshell_v6.exe`) as an extra resource

## Toolchain And Dependencies

You need these installed on the machine:

- Windows 10/11 (for this project setup)
- Node.js 18+ (Node.js 20+ recommended)
- npm (comes with Node.js)
- GCC toolchain (only required when rebuilding the shell binary)

Project dependencies used for packaging:

- `electron`
- `electron-builder`
- `vite`
- app dependencies from `package.json`

Install dependencies:

```powershell
cd terminal-app
npm install
```

## Required Resources

Before packaging, verify these resources exist:

- `terminal-app/build/icon.ico` (app + installer branding icon)
- `shell-core/myshell_v6.exe` (bundled shell engine)

If shell binary is stale or missing, rebuild it:

```powershell
cd terminal-app
npm run build:shell
```

## Packaging Configuration (package.json)

Installer behavior is controlled by the `build` section in `terminal-app/package.json`.

Key points configured:

- `appId`: app identity (`com.apnashell.desktop`)
- `productName`: installer/app display name (`apnaShell`)
- `files`: what goes into app package
- `extraResources`: includes `../shell-core/myshell_v6.exe`
- `directories.output`: writes artifacts to `release/`
- `win.target`: `nsis`
- `win.icon`: `build/icon.ico`
- `win.publisherName`: publisher metadata
- `nsis.installerIcon` and `nsis.uninstallerIcon`: `build/icon.ico`
- `nsis.oneClick`: disabled (wizard-style installer)
- `nsis.allowToChangeInstallationDirectory`: enabled

Also include package metadata such as:

- `author`

## Build Commands And Methodology

There are two main packaging commands:

1. Generic dist build:

```powershell
cd terminal-app
npm run dist
```

This runs:

- renderer production build (`vite build`)
- `electron-builder` packaging flow

1. Windows dist with shell rebuild (safer for release):

```powershell
cd terminal-app
npm run dist:win
```

This runs:

- shell rebuild (`npm run build:shell`)
- renderer build
- Windows NSIS packaging

Recommended release methodology:

1. Pull latest code and verify branch state.
2. Run `npm install` if dependencies changed.
3. Rebuild shell binary (`npm run build:shell`).
4. Build and package (`npm run dist:win`).
5. Verify output in `terminal-app/release/`.
6. Install locally once and sanity-check startup + shell execution.

## Important Validation Checks

After build completes, verify:

- installer exists at `release/apnaShell Setup <version>.exe`
- `release/win-unpacked/` exists
- app launches and opens terminal UI
- shell commands run in packaged app
- cwd initializes correctly in installed app

Optional extra checks:

- install/uninstall cleanly
- desktop and start menu shortcuts are created

## Important Points To Keep In Mind

1. Code signing

- Current setup can build unsigned installers.
- Unsigned installers often trigger Windows SmartScreen warnings.
- For broad distribution, add code signing certificates and signing config.

1. Metadata quality

- Keep `author` and publisher fields populated to avoid builder warnings.
- Keep version in `package.json` updated before release.

1. Shell binary dependency

- Installer bundles `shell-core/myshell_v6.exe` via `extraResources`.
- If that file is missing, packaging will fail.
- If code changed in `shell-core/myshell.c`, rebuild shell before packaging.

1. Icon assets

- Ensure `build/icon.ico` exists and is valid.
- This icon is used for app executable and NSIS installer branding.

1. Antivirus/Defender sensitivity

- Fresh unsigned binaries may be scanned aggressively.
- Use release builds, avoid ad-hoc repacks, and prefer signed binaries for trust.

## Troubleshooting

`electron-builder is not recognized`

- Run `npm install` in `terminal-app`.
- Verify `electron-builder` is present in `devDependencies`.

`author is missed in package.json`

- Add `author` field to `package.json`.

`default Electron icon is used`

- Add icon path in `build.win.icon` and ensure file exists.

`extraResources file not found`

- Confirm `../shell-core/myshell_v6.exe` exists from `terminal-app` path.
- Run `npm run build:shell`.
